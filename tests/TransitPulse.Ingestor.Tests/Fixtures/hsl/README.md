# HSL HFP fixtures

Real `VP` messages from the HSL High-Frequency Positioning feed (`mqtt.hsl.fi:8883`, topic
`/hfp/v2/journey/ongoing/vp/#`), taken unchanged from the raw archive of 2026-10-20 and 2026-10-22.

- `vp.jsonl` — one archived message per line: `case`, `receivedAt`, MQTT `topic` and `payload`. The payload is kept
  as a string, byte for byte: re-serializing it would turn `"spd":0.00` into `0.0` and hide format differences.
- `vp.expected.jsonl` — the position each line must normalize to, in the `positions.raw` value format
  (`PositionMessage`), or `null` when the message is skipped. Computed by a separate implementation of the rules
  and reviewed line by line, not generated by the normalizer under test.

Each line covers one case measured on 15.5 M archived messages (four days):

| # | Case | Why it is here |
|---|---|---|
| 1–2 | Bus, tram on a journey | Baseline mapping; `dl` > 0 means ahead, so the delay is negative |
| 3–4 | Metro | Location `MAN`, never a delay; whole-second `tst`, integer `spd`/`hdg` of 0 |
| 5 | Train on a journey | A late train (`dl` < 0) |
| 6 | Train on a placeholder journey | `jrn` 9999, parked for hours: no trip, route or delay |
| 7 | Ferry | The only mode with a measured occupancy percentage; no `jrn` |
| 8 | Full bus | `occu` 100, sent by a few buses only |
| 9 | No coordinates | Odometer-only location: the message is skipped |
| 10 | Implausible delay | \|`dl`\| > 2 h: the position is kept without a delay |
| 11–14 | Journey start times | After midnight (`24:00`), waiting before an after-midnight departure, a 03:xx night journey of the day before (`27:06`), the first journeys of the day |
