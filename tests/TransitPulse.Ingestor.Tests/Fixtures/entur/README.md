# Entur SIRI-VM fixtures

Real SIRI-VM responses for Bergen and Vestland (`GET https://api.entur.io/realtime/v1/rest/vm?datasetId=SKY&maxSize=1500&requestorId=…`),
taken from the raw archive and trimmed: the envelope and the chosen `VehicleActivity` elements are kept byte for byte
and in their original order, each record on its own line; the other records are removed. The one change inside the
envelope: `RequestMessageRef` echoes the collector's subscription id (`requestorId`), which stays valid until the
collector renews it, so it is replaced with the zero GUID (the normalizer does not read it).

- `vm-full.xml` — the full snapshot a new `requestorId` returns: the first response after a collector restart,
  received 2026-10-24 20:49:37.798 UTC (376 records, 10 kept). It repeats every journey of the evening, so most of it
  is records of finished journeys, minutes to hours old.
- `vm-delta.xml` — an ordinary incremental response, received 2026-10-23 11:05:20.157 UTC (468 records, 11 kept).
- `*.expected.jsonl` — one line per kept record, in order: the position it must normalize to, in the
  `positions.raw` value format (`PositionMessage`), or `null` when the record is skipped. Computed by a separate
  implementation of the rules and reviewed line by line, not generated by the normalizer under test.
