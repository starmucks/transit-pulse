# MBTA GTFS Realtime fixtures

A real MBTA `VehiclePositions` snapshot (`GET https://cdn.mbta.com/realtime/VehiclePositions.pb`), taken from the raw
archive and trimmed: the header and the chosen entities are kept unchanged and in their original order, the other
entities are removed, and the message is encoded again by the reference protobuf library (protobuf has no byte-level
cut, so the bytes differ from the archived payload while every field value is the same).

- `vp.pb` — the snapshot received 2026-10-26 00:00:03.443 UTC (347 entities, 10 kept).
- `vp.expected.jsonl` — one line per kept entity, in order: the position it must normalize to, in the
  `positions.raw` value format (`PositionMessage`), or `null` when it is skipped. Computed by a separate
  implementation of the rules and reviewed line by line, not generated by the normalizer under test.

| # | Case | Why it is here |
|---|---|---|
| 1 | Bus `y1256`, stopped, bearing 0 | Baseline mapping; a bearing of 0 that is set stays 0 (north) |
| 2 | Bus, `MANY_SEATS_AVAILABLE` | Measured occupancy |
| 3 | Bus, `FEW_SEATS_AVAILABLE` | Occupancy above the default level |
| 4 | Green Line car, 13.5 min old | Older than 5 min at receive time: skipped |
| 5 | Orange Line train, 6 carriages | Carriage details are not part of the model; no occupancy for the train as a whole |
| 6 | Green Line car, 2 carriages | Light rail; carriage details ignored |
| 7 | Commuter rail `1718` | Speed set (the feed's only speeds come from trains); bearing unset, so `null`, not 0; trip id in another format |
| 8 | Bus without occupancy | Unset occupancy stays `null`, not `EMPTY` |
| 9 | Bus on a canceled trip | A position is still a position; trip id with a suffix (`-OL1`) |
| 10 | Red Line train on an added trip | Trip id not in the static schedule (`ADDED-…`), passed on as is |

No record carries a delay: GTFS-RT positions have none, so every `delaySec` is absent.
